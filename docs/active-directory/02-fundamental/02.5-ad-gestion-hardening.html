Active Directory

Gestión y hardening

Fundamental

De qué trata

Mecanismos que sirven para administrar y proteger AD. Cada uno es útil para el administrador, pero también es un lugar donde un atacante puede ganar poder o persistencia.

GPO
Gestión masiva: configurar muchos usuarios y equipos a la vez.
AdminSDHolder y adminCount
Mecanismo de auto-reparación para las cuentas privilegiadas.
dsHeuristics
Configuración global que puede debilitar esa protección.
sIDHistory
Legítimo para migraciones, pero mal controlado es una puerta trasera de escalación.

Idea clave: Para cada concepto, retené el mecanismo y el riesgo: qué hace para el administrador y qué puede hacer un atacante con él.

Conceptos

1

GPO (Group Policy Object)

Colección de configuraciones de política para usuarios y/o equipos.

  • Cada GPO tiene su propio GUID.
  • Se linkea a nivel domain, OU o site, y eso define su alcance.
  • Riesgo: si un atacante puede editar, o crear y linkear un GPO, puede desplegar cambios maliciosos a gran escala: scripts, membership de grupos locales, desactivar defensas.
2

AdminSDHolder

Objeto especial que actúa como template de seguridad (DACL) para todos los miembros de grupos protegidos: Domain Admins, Enterprise Admins, Schema Admins, etc.

  • El proceso SDProp (Security Descriptor Propagator) corre en el PDC Emulator, cada 60 minutos por default, y revierte cualquier DACL de un miembro protegido que no coincida con el template.
  • No se puede modificar de forma persistente la DACL de un solo miembro protegido: SDProp lo revierte.
  • Para un cambio permanente hay que modificar el AdminSDHolder mismo, y el cambio se propaga a todos por igual. Es todo o nada.
3

adminCount

Atributo que le dice a SDProp a quién proteger.

1
Protegido: su DACL se revierte al template.
0 o sin setear
No protegido.
  • Clave: cuando alguien sale de un grupo privilegiado, este atributo no se resetea solo a 0. Queda en 1, salvo que alguien lo limpie a mano.
  • Útil para threat hunting: buscar adminCount=1 arma una lista de cuentas que en algún momento tuvieron privilegios, actuales o ex.
4

dsHeuristics

Atributo de tipo string, a nivel forest, que controla configuraciones globales. Entre ellas, permite excluir de la protección de SDProp a los 4 grupos de operadores integrados: Account Operators, Server Operators, Print Operators y Backup Operators. No permite excluir cualquier grupo.

  • Riesgo: un grupo excluido vía dsHeuristics deja de estar protegido por AdminSDHolder, y su DACL ya no se revierte. Es una técnica de persistencia avanzada.
5

sIDHistory

Atributo que guarda los SIDs previos que tuvo un objeto. Su uso legítimo son las migraciones entre domains, para no perder accesos.

  • Riesgo: si el SID filtering no está habilitado en los trusts (el control que descarta SIDs que no corresponden al domain de origen), un atacante que escribe en el sIDHistory de una cuenta puede inyectar el SID de un grupo privilegiado (por ejemplo Domain Admins o Enterprise Admins) y heredar sus permisos sin estar realmente en ese grupo.

Para no confundirse

  • Puedo cambiar la DACL de una sola cuenta protegida y que el cambio quede: no. SDProp la revierte, salvo que se modifique el AdminSDHolder, que afecta a todos por igual.
  • adminCount=1 no significa que la cuenta sea admin hoy: puede ser un ex-miembro de un grupo privilegiado.
  • AdminSDHolder protege a los grupos de su lista, pero dsHeuristics puede dejar afuera a los operadores integrados (Account, Server, Print y Backup Operators).
  • El sIDHistory no es un grupo: son SIDs viejos de la cuenta. Pero si uno de ellos es el de un grupo privilegiado, el sistema trata a la cuenta como si fuera miembro.
