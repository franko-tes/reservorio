Active Directory

Almacenamiento, recuperación y herramientas

Fundamental

De qué trata

Tres preguntas prácticas sobre AD: dónde vive la información, qué pasa cuando algo se borra y con qué se administra todo.

Dónde vive la data
SYSVOL (compartida y legible por cualquier usuario autenticado) y NTDS.DIT (la base completa, con los secretos).
Qué pasa al borrar
Tombstone y AD Recycle Bin.
Con qué se administra
ADUC (amigable, para el día a día) y ADSI Edit (quirúrgica).

Idea clave: SYSVOL lo puede leer cualquier usuario autenticado; NTDS.DIT guarda los secretos. Un objeto borrado no desaparece al instante.

Conceptos

1

SYSVOL

Carpeta compartida presente en todos los DCs de un domain. Contiene archivos legibles por cualquier usuario autenticado del domain: policies del sistema, configuraciones de GPO, scripts de logon y logoff y otros scripts operativos.

  • Se replica automáticamente entre DCs (con FRS, o con DFS-R en versiones modernas).
  • Se accede típicamente como \\dominio.local\SYSVOL.
  • Relevante: es el lugar físico donde buscar scripts de logon o contenido de GPO sospechoso.
2

NTDS.DIT

El corazón de AD

Archivo de base de datos que hay en cada DC, ubicado en C:\Windows\NTDS\. Contiene usuarios, grupos, membership y los password hashes de todos los usuarios del domain.

  • Objetivo típico tras un domain compromise completo: se extrae con ntdsutil o con volume shadow copy, y después se usa pass-the-hash o se crackea con Hashcat.
  • Si está habilitada la opción “Store passwords using reversible encryption”, también guarda las passwords en una forma que se puede revertir a texto plano. Es una bandera roja si la ves activa.
3

Tombstone

Cuando se borra un objeto, no desaparece al instante: queda como tombstone durante el Tombstone Lifetime (es un valor del forest, no de cada DC: por defecto 180 días en forests creados con Windows Server 2003 SP1 o posterior, y 60 en los anteriores).

  • Pierde la mayoría de sus atributos y queda en el container Deleted Objects.
  • Es recuperable, pero sin los atributos que perdió.
  • Cumplido el plazo, el objeto se elimina definitivamente (garbage collection).
4

AD Recycle Bin

Mejora sobre el tombstone, disponible desde Windows Server 2008 R2. Hay que habilitarla, y si está habilitada preserva la mayoría de los atributos del objeto borrado, lo que permite una restauración mucho más completa.

  • Se habilita a nivel forest y, una vez habilitada, no se puede deshabilitar. Requiere un forest functional level de Windows Server 2008 R2 o superior.
  • El plazo para recuperar un objeto depende de la configuración (msDS-deletedObjectLifetime). Si no se especifica un valor, se usa el del tombstone lifetime.
5

ADUC (Active Directory Users and Computers)

Consola gráfica clásica para administrar usuarios, grupos, equipos y contactos. Todo lo que se hace desde ahí también se puede hacer con PowerShell.

6

ADSI Edit

Herramienta de bajo nivel que da acceso a prácticamente cualquier atributo de cualquier objeto, incluso los que ADUC no expone (por ejemplo dsHeuristics, o adminCount a mano).

  • Es potente y peligrosa: un cambio mal hecho puede romper el ambiente.
  • Se usa solo cuando ADUC no alcanza.

Para no confundirse

  • Un objeto borrado desaparece al instante: no. Queda como tombstone, y si la Recycle Bin está habilitada, conserva casi todos sus atributos.
  • SYSVOL y NTDS.DIT no son lo mismo: SYSVOL es una carpeta compartida con policies y scripts; NTDS.DIT es la base de datos con los hashes de todas las cuentas.
  • Tombstone y Recycle Bin: con tombstone se recupera el objeto sin los atributos perdidos; con la Recycle Bin, casi completo.
  • ADUC es la herramienta del día a día; ADSI Edit se reserva para lo que ADUC no muestra.
