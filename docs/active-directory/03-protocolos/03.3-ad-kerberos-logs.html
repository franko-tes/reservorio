Active Directory

Kerberos en los logs

Protocolos

De qué trata

Un inicio de sesión o un acceso a un servicio deja eventos en dos tipos de máquinas distintas:

  • En los DCs: el KDC registra los tickets que emite o rechaza (4768, 4769, 4771).
  • En el equipo al que se accede: Windows registra la sesión que se crea o se rechaza (4624 y 4625).

Idea clave: Los eventos de Kerberos registran pedidos de tickets. Los 4624 y 4625 registran sesiones creadas o rechazadas en un equipo. No son equivalentes ni van uno a uno.

Dónde se genera cada evento

4768
En el DC. Se pidió un TGT (éxito o falla). Subcategoría de auditoría: Audit Kerberos Authentication Service.
4771
En el DC. Falló la preautenticación. Misma subcategoría.
4769
En el DC. Se pidió un ticket de servicio (éxito o falla). Subcategoría: Audit Kerberos Service Ticket Operations.
4624
En el equipo al que se accede (el destino, no el origen). Sesión creada. Subcategoría: Audit Logon.
4625
En el equipo donde se intentó el logon. Sesión rechazada. Subcategorías: Audit Logon y Audit Account Lockout.

Si la subcategoría no está activada, el evento no se genera.

Qué evento deja cada mensaje del proceso (ver 03.2)

Mensajes 1 y 2 (AS)
4768 si se emitió el TGT o si falló por un motivo distinto de la preautenticación. 4771 si falló la preautenticación.
Mensajes 3 y 4 (TGS)
4769, con éxito o con falla.
Mensajes 5 y 6 (AP)
Ningún evento de Kerberos en el DC, porque el KDC no participa. El rastro queda en el equipo o servidor al que se accede: un 4624 (o un 4625 si se rechaza).

Evento 4768: se pidió un TGT

Campos clave

Account Name
La cuenta para la que se pidió el TGT. Las cuentas de equipo terminan en $.
Client Address
La IP de origen. ::1 es local.
Ticket Encryption Type
El cifrado del TGT emitido.
Pre-Authentication Type
2 = password, 15 = smart card, 138 = Kerberos armoring, 0 = sin preautenticación.
Result Code
0x0 = éxito.

Códigos de resultado de interés

0x6
El usuario no existe. Repetido, puede indicar enumeración de cuentas.
0x12
Cuenta deshabilitada, vencida o bloqueada.
0x19
Se requiere preautenticación adicional.

El 0x18 no aparece acá: va en el 4771.

Evento 4771: falló la preautenticación

Failure Code 0x18
Preautenticación inválida, normalmente una password incorrecta.
Failure Code 0x17
Password vencida.

No se genera para cuentas con “Do not require Kerberos preauthentication”.

Evento 4769: se pidió un ticket de servicio

Campos clave

Account Name
Quien pide, en formato UPN (por ejemplo, usuario@techcorp.local).
Service Name
La cuenta o equipo para el que se pide el ticket.
Client Address
La IP de origen.
Ticket Encryption Type
El cifrado del ticket emitido.
Failure Code
0x0 = éxito.
Logon GUID
Permite correlacionar con el 4624.

Códigos de falla frecuentes

0x7
El servicio no existe en AD.
0x12
Cuenta deshabilitada, vencida o bloqueada.
0x20
Ticket vencido. Es muy común y tiene poca relevancia de seguridad.
0x25
Diferencia de hora mayor a la tolerancia (ver 03.2).

Tipos de cifrado en los eventos

0x12
AES256. Valor esperado en un entorno moderno.
0x11
AES128. Valor esperado en un entorno moderno.
0x17
RC4. Era el cifrado por defecto antes de Windows Server 2008 y Vista.
0x1 y 0x3
DES. No deberían aparecer.
  • Relevante: en un entorno moderno, lo esperable es AES (0x11 o 0x12). Cualquier otro valor merece revisarse, porque indica un cifrado más débil o un equipo o servicio antiguo (ver 02.9). Microsoft recomienda alertar ante esos valores.

Eventos 4624 y 4625: la sesión en el equipo

Campos clave del 4624

Logon Type
El tipo de inicio de sesión (lista abajo).
Authentication Package
Kerberos, NTLM o Negotiate.
Package Name (NTLM only)
NTLM V1, NTLM V2 o LM. Solo se completa si el paquete es NTLM.
Key Length
Siempre 0 para Kerberos.
Source Network Address
La IP del cliente.

El 4625 tiene Logon Type, Authentication Package, Source Network Address, Workstation Name, y los códigos Status y Sub Status.

Logon Type

2, Interactive
Alguien inició sesión en el equipo.
3, Network
Acceso por la red, por ejemplo a un share.
4, Batch
Tareas programadas, sin intervención del usuario.
5, Service
El Service Control Manager inició un servicio.
7, Unlock
Se desbloqueó el equipo.
8, NetworkCleartext
Logon de red con la password sin hashear.
9, NewCredentials
Credenciales distintas para conexiones salientes.
10, RemoteInteractive
Escritorio Remoto o Terminal Services.
11, CachedInteractive
Credenciales en caché; no se contactó a un DC (ver 03.1).

Códigos de falla del 4625

0xC000006D
Usuario incorrecto o información de autenticación incorrecta.
0xC000006A
Password incorrecta.
0xC0000064
El usuario no existe. Varios seguidos pueden indicar enumeración.
0xC0000072
Cuenta deshabilitada.
0xC0000234
Cuenta bloqueada.

¿Kerberos o NTLM en un 4624?

El campo Authentication Package dice qué paquete se usó. Con Kerberos o NTLM queda claro, pero con Negotiate no siempre se puede saber cuál de los dos se usó:

Kerberos
Se usó Kerberos.
NTLM
Se usó NTLM, y el campo Package Name dice qué versión.
Negotiate
Windows eligió entre Kerberos y NTLM, y el 4624 solo no siempre lo aclara. Si hay un 4768 o 4769 correspondiente en el DC, se usó Kerberos. Si no hay, no se puede asegurar, porque el ticket puede estar en caché.

Cómo se ve en los logs

Cada línea es un escenario típico, con el DC y el equipo:

Logon interactivo exitoso
4768 en el DC, y suele verse también un 4769 para el propio equipo. En el equipo, 4624 tipo 2.
Acceso a un share
4769 en el DC (si el ticket de servicio no estaba en caché) y 4624 tipo 3 en el servidor. El Logon GUID del 4769 permite correlacionarlos.
Password incorrecta en el logon
4771 con 0x18 en el DC y 4625 en el equipo.
Usuario inexistente
4768 con 0x6 en el DC y 4625 en el equipo.
Sin DC alcanzable
4624 tipo 11 en el equipo, sin ningún evento de Kerberos en los DCs.

Señales para vigilar

  • Riesgo: muchos 4771 con 0x18 en poco tiempo contra una cuenta importante: posible fuerza bruta.
  • Riesgo: 4768 con 0x6 o 4625 con 0xC0000064 repetidos: posible enumeración de cuentas.
  • Riesgo: 4625 con 0xC000006D o 0xC000006A en ráfagas contra cuentas críticas o de servicio.
  • Riesgo: un 4769 con cifrado RC4 (0x17) para una cuenta de servicio, en un entorno que ya usa AES. Es la señal que suele usarse para detectar Kerberoasting (ver 02.4). Tiene falsos positivos con servicios viejos que solo soportan RC4.
  • Riesgo: cifrado DES (0x1 o 0x3) en cualquier evento.
  • Riesgo: Authentication Package NTLM donde NTLM no debería usarse.
  • Relevante: IPs de origen fuera de los rangos internos, o ::1 en un DC para cuentas que no deberían iniciar sesión ahí.
  • Relevante: el 0x25 indica problema de hora, no un ataque.
  • Relevante: el 0x20 es ruido normal.
  • Relevante: una cuenta administrativa con Logon Type 4 o 5 es una combinación inusual.

Nombres de campo en el XML

Para consultas en el SIEM, el XML usa otros nombres: TargetUserName, ServiceName, IpAddress, IpPort, Status, SubStatus, TicketEncryptionType, PreAuthType, LogonType, AuthenticationPackageName, WorkstationName.

Para no confundirse

  • Un 4768 es un acceso a un recurso: no. Es el pedido de un TGT, normalmente al iniciar sesión, y el TGT solo sirve para pedir tickets de servicio.
  • Un 4769 exitoso significa que el servicio aceptó al usuario: no. Significa que el KDC emitió el ticket. La decisión de acceso la toma el servicio (ver 03.2).
  • 4624 es el evento de Kerberos: no. Es la sesión creada, con Kerberos o con NTLM.
  • Un 4624 tipo 3 implica Kerberos: no. Hay que mirar el Authentication Package.
  • Cada acceso a un servicio deja un 4769: no necesariamente. Mientras el ticket de servicio siga en la caché del cliente y no venza (ver 03.2), se reutiliza sin volver a pedirlo.
  • Si no hay 4768, no hubo inicio de sesión: no. El logon con credenciales en caché deja un 4624 tipo 11 sin ningún evento de Kerberos.
