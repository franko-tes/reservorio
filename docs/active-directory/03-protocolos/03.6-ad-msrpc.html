Active Directory

MSRPC

Protocolos

De qué trata

RPC (Remote Procedure Call) permite que un programa llame a una función que se ejecuta en otro equipo, como si fuera local. El programa hace la llamada con sus parámetros; RPC los envía por la red, el otro equipo ejecuta la función y le devuelve el resultado.

MSRPC es la implementación de Microsoft. En una llamada hay tres niveles, de lo general a lo concreto:

RPC
El mecanismo: lleva una llamada de un equipo a otro y trae la respuesta. Es siempre el mismo.
Interfaz
Un grupo de funciones sobre un mismo tema que ofrece un servidor, con sus parámetros y resultados. Por ejemplo, samr, con las funciones sobre cuentas.
Función
Una operación concreta dentro de la interfaz. Por ejemplo, en samr, devolver los miembros de un grupo.

Por ejemplo, para ver los miembros de Domain Admins, el equipo llama por RPC a la función de samr del DC que devuelve los miembros de un grupo. El DC la ejecuta y RPC trae la lista de vuelta.

AD usa MSRPC para muchas operaciones remotas, cada una por una interfaz distinta:

  • consultar y administrar cuentas (samr) o traducir nombres y SIDs (lsarpc),
  • establecer el canal seguro entre un equipo y el DC (netlogon),
  • replicar el directorio entre DC (drsuapi).

Idea clave: RPC es el mecanismo para hacer la llamada. Cada interfaz define qué funciones se pueden llamar. Lo que importa en AD son las interfaces: pedir los miembros de un grupo con samr no es lo mismo que pedir los hashes de las passwords con drsuapi, aunque las dos llamadas viajen por RPC.

Cómo se llega al servicio

  • Endpoint mapper (puerto 135, TCP): el cliente le pregunta en qué puerto está la interfaz que quiere, y el servidor le responde con un puerto asignado dinámicamente.
  • Puertos dinámicos: desde Windows Server 2008, el rango por defecto es 49152 a 65535.
  • Named pipes sobre SMB (puerto 445): otra forma de llegar a las mismas interfaces. El endpoint mapper también ofrece su servicio por named pipes.
  • Relevante: no todo RPC pasa por el 135. Según la interfaz, puede ir por un puerto dinámico o por SMB.

Las interfaces que importan en AD

lsarpc
Consulta de políticas de seguridad y traducción entre nombres y SIDs.
netlogon
El canal seguro entre un equipo y el DC. Por ese canal, un servidor le pasa al DC las validaciones NTLM de cuentas del domain (ver 03.4). En un equipo miembro usa named pipes; en un DC también usa RPC sobre TCP.
samr
Administración remota de usuarios, grupos y equipos.
drsuapi
Replicación entre DC. Un DC pide a otro los cambios de una partición del directorio.
  • Riesgo: con samr, un usuario con pocos privilegios puede enumerar usuarios, incluidas las cuentas privilegiadas, y grupos con sus miembros. Es un punto de partida para un atacante.
  • Por defecto, en los DC con Windows Server 2016 o posterior pueden consultar todos (Everyone). En los demás equipos, desde Windows 10 1607 y Windows Server 2016, solo el grupo Administrators local; en versiones anteriores no hay control.
  • La política “Network access: Restrict clients allowed to make remote calls to SAM” define quién puede consultar. Microsoft advierte que puede romper herramientas que enumeran cuentas, y ofrece un modo solo de auditoría para probarla.

Autenticación

Una llamada RPC se autentica, en general, con Kerberos o NTLM (ver 03.1 a 03.4). netlogon es la excepción: el equipo y el DC se autentican con la password de la cuenta del equipo, que conocen los dos. Que transporte validaciones NTLM no quiere decir que se autentique con NTLM.

Replicación y derechos

  • Un DC replica pidiendo los cambios a otro DC mediante drsuapi.
  • Para pedir replicación hace falta tener sobre el domain los derechos Replicating Directory Changes y Replicating Directory Changes All. Este segundo permite obtener atributos sensibles, como los hashes de las passwords.
  • Los DC de escritura tienen estos derechos. También los tienen algunas cuentas de servicio, como la que usa Microsoft Entra Connect para sincronizar passwords.
  • Riesgo: una cuenta que no es un DC pero tiene estos derechos puede pedir la replicación y obtener los hashes de cualquier cuenta. Esa técnica se llama DCSync.
  • Si no se usa la sincronización de passwords, Microsoft recomienda quitarle estos permisos a la cuenta de Entra Connect.

Eventos y señales

Evento 4662

Una operación sobre un objeto de AD. Subcategoría: Audit Directory Service Access.

Properties
Muestra los GUID de los derechos o clases involucrados. Los de replicación son 1131f6aa-9c07-11d1-f79f-00c04fc2dcd2 (Replicating Directory Changes) y 1131f6ad-9c07-11d1-f79f-00c04fc2dcd2 (Replicating Directory Changes All).

Señales

  • Riesgo: un 4662 con el GUID de Replicating Directory Changes All hecho por una cuenta que no es de un DC.
  • Relevante: se genera solo si esa subcategoría está activada en los DC y el objeto tiene una SACL que cubra la operación. Sin las dos, no hay evento.

Para no confundirse

  • DCSync copia el archivo NTDS.dit: no. Copiar NTDS.dit requiere acceso al propio DC. DCSync no lo toca: pide la replicación por la red con drsuapi, usando los derechos de replicación.
  • RPC siempre usa el puerto 135: no. El 135 solo sirve para averiguar el puerto. La llamada puede ir por un puerto dinámico o por SMB (445).
  • RPC es un protocolo de autenticación: no. Es el mecanismo de llamada. La autenticación la hace otro protocolo, en general Kerberos o NTLM.
  • Solo los DC pueden pedir replicación: no. Cualquier cuenta con los derechos de replicación puede hacerlo.
