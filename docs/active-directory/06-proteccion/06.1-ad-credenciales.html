1. De qué trata

Muchos ataques en un domain no rompen nada: usan cuentas que ya existen. Si la password del administrador local es igual en todos los equipos, o si una cuenta con mucho poder inicia sesión en cualquier equipo, uno solo comprometido abre el resto. Este contenido cubre tres medidas sobre las cuentas:

  • LAPS
  • las gMSA
  • el uso cuidado de las cuentas privilegiadas

Para los mecanismos de AD que también usa un atacante, ver 02.5.

Idea clave: LAPS, las gMSA y el cuidado de las cuentas privilegiadas apuntan a lo mismo: que una cuenta comprometida no abra el resto del domain.

2. LAPS: la password del administrador local

  • Qué es: Windows LAPS (Local Administrator Password Solution) administra y respalda automáticamente la password de una cuenta de administrador local en equipos unidos a Active Directory.
  • Dónde se guarda: en Active Directory (en el objeto equipo, protegida con permisos y, si se activa, cifrada; Microsoft recomienda activarlo) o, para equipos unidos a Microsoft Entra, en Entra ID (siempre cifrada). En un equipo híbrido se elige uno de los dos, no ambos.
  • Controladores de domain: también puede administrar la password de la cuenta DSRM (modo de restauración de servicios de directorio) de los DC.
  • Disponibilidad: viene integrado en Windows y Windows Server desde la actualización de abril de 2023. No requiere instalar el LAPS legacy.
  • Riesgo: usar las mismas credenciales de administrador local en todos los equipos. Con la password de uno se entra a todos. Microsoft lista como beneficio de LAPS la protección contra pass-the-hash (ver 03.4) y contra el movimiento lateral.
  • Relevante: quién puede leer esa password en el objeto equipo se controla con permisos (ver 02.4).

3. gMSA: cuentas de servicio sin password manual

  • Qué es: una group Managed Service Account es una cuenta de servicio donde Windows administra la password, en lugar de depender de un administrador.
  • Cómo funciona: el DC calcula la password a partir de una clave del Key Distribution Service; los equipos autorizados la obtienen contactando un DC.
  • Varios equipos: una misma gMSA sirve a un servicio que corre en varios servidores, sin sincronizar passwords entre ellos.
  • Relevante: nadie elige ni escribe la password, así que no queda una password débil o repetida en una cuenta de servicio. Para el ataque contra cuentas de servicio, ver 03.2.
  • Relevante: las gMSA no aplican a sistemas anteriores a Windows Server 2012.

4. Cuentas privilegiadas

  • Qué cuentas proteger:
    • Los tres grupos de más privilegio: por defecto son Enterprise Admins, Domain Admins y Administrators. Hay que protegerlos, y también a cualquier otro grupo con privilegios elevados (qué revisar, ver 04.2 y 04.4).
    • Cuenta diaria y cuenta administrativa: Microsoft indica no usar cuentas de alto privilegio para tareas administrativas cotidianas y darles solo los privilegios que necesitan (ver 04.1).
  • Desde dónde se usan:
    • Equipos administrativos seguros: esos equipos no corren correo, navegador ni ofimática, y nunca se administra un sistema de confianza desde uno de menor confianza.
    • Riesgo: iniciar sesión con una cuenta privilegiada en equipos sin protección o navegando por internet. Microsoft lo señala como comportamiento que expone las credenciales. Para el acceso remoto, ver 04.3 y 04.4.
    • Domain Admins fuera de servidores miembro y estaciones: la membresía en Domain Admins solo debería hacer falta para armar el domain o recuperarlo de un desastre, no para tareas diarias. Microsoft propone una GPO vinculada a las OU de servidores miembro y estaciones que le asigne a Domain Admins los derechos de denegar el inicio de sesión local, por red, por Remote Desktop, como servicio y como tarea programada (derechos de inicio de sesión, ver 04.3; GPO, ver 05.1).
  • Cuándo y cómo:
    • Membresía temporal: eliminar la membresía permanente en grupos de alto privilegio y dar membresía temporal cuando se necesite.
    • MFA: Microsoft recomienda exigir autenticación multifactor al usar cuentas privilegiadas o hacer tareas administrativas.
    • Logs: los cambios en los grupos privilegiados quedan en los logs (ver 04.5).

5. Para no confundirse

  • Windows LAPS y el LAPS antiguo son lo mismo: no. Windows LAPS viene integrado en Windows y no requiere el LAPS legacy.
  • Una gMSA es una cuenta de usuario con password larga: no. La password la calcula el DC y los equipos autorizados la obtienen; nadie la tipea.
  • Con el grupo Domain Admins protegido alcanza: no. Son tres los grupos de mayor privilegio, más los que la organización haya elevado.
  • La cuenta de admin puede usarse también para el día a día: no. Se separa de la cuenta diaria.
