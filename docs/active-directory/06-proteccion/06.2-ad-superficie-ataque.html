1. De qué trata

Cada servicio, cada permiso de más y cada equipo sin parchear es un punto por donde un atacante puede entrar o avanzar. Este contenido cubre cómo reducir esos puntos de entrada:

  • parches;
  • Restricted Groups;
  • control de aplicaciones;
  • servidores, administradores locales y RDP;
  • revisión periódica de permisos y membresías.

Para las cuentas y credenciales, ver 06.1.

Idea clave: Cada medida de este contenido achica la superficie de ataque: menos puntos por donde un atacante puede entrar o avanzar.

2. Parches: WSUS y Configuration Manager

  • WSUS: es un rol de servidor de Windows Server que permite a los administradores desplegar las actualizaciones de productos Microsoft, y se administra desde una consola.
  • Relevante: WSUS está obsoleto (deprecated) y no recibe funciones nuevas, pero sigue soportado en producción y recibe actualizaciones de seguridad y calidad.
  • Configuration Manager (SCCM): ayuda a rastrear y aplicar las actualizaciones de software en los clientes de la organización. Las actualizaciones se despliegan de forma manual o automática, con reglas de despliegue automático.

3. Restricted Groups

  • Qué es: una configuración de GPO (Computer Configuration → Windows Settings → Security Settings → Restricted Groups) que define dos propiedades para grupos sensibles: Members y Member Of.
  • Members: define quién pertenece y quién no al grupo. Al aplicarse, se quita a todo miembro actual que no figure en la lista, excepto el administrador en el grupo Administrators, y se agrega a quien falte. Por ejemplo, en una GPO vinculada a la OU Servidores de techcorp.local, con Members del grupo Administrators solo con el Administrator local y Domain Admins, cualquier otro miembro se quita en la siguiente actualización de la política (ver 05.2).
  • Member Of: solo se refuerza la inclusión: el grupo no se quita de otros grupos.
  • Relevante: está pensado para grupos locales de estaciones y servidores miembro. Microsoft no soporta usarlo para administrar la membresía de grupos de domain, que se administran con las herramientas de AD. Se aplica con GPO (ver 05.1) y los grupos locales se explican en 04.4.

4. Control de aplicaciones: SRP y AppLocker

  • Software Restriction Policies (SRP): un mecanismo basado en Group Policy para identificar software y controlar si puede ejecutarse en el equipo.
  • AppLocker: ayuda a los administradores a controlar qué aplicaciones y archivos pueden ejecutar los usuarios.
  • Relevante: AppLocker permite aplicar su política en modo solo auditoría: se permite toda ejecución, pero queda registrada en los logs de eventos.
  • Estado actual: SRP está obsoleta (deprecated) desde Windows 10 versión 1803. AppLocker ya no recibe funciones nuevas, solo correcciones de seguridad. Microsoft recomienda App Control for Business.
  • Riesgo: AppLocker es una función de defensa en profundidad (defense-in-depth), no una barrera de seguridad defendible: ayuda a evitar que los usuarios ejecuten aplicaciones no aprobadas, pero no hay que tratarlo como un límite infranqueable.

5. Servidores, administradores locales y RDP

  • Controladores de domain: no se usa un navegador web en un DC, y el acceso a internet desde y hacia los DC debe estar estrictamente controlado. En organizaciones que mantienen Active Directory solo on-premises, Microsoft recomienda restringirlo por completo.
  • Administradores locales: Microsoft recomienda restringir las cuentas Administrator locales de servidores miembro y estaciones de la misma manera que las del domain.
  • Remisiones: los derechos de inicio de sesión se explican en 04.3, el grupo Remote Desktop Users en 04.4, y la restricción de Domain Admins en 06.1.

6. Revisión periódica de permisos y membresías

  • Qué revisar: los administradores locales, la cantidad de Domain Admins y de Enterprise Admins, el acceso a recursos compartidos y la membresía en grupos privilegiados (qué mirar, ver 04.2 y 04.4).
  • Por qué: Microsoft señala que los ataques de robo de credenciales dependen de que se den privilegios excesivos a cuentas y de asignar demasiados usuarios a grupos privilegiados.
  • Alertas: Microsoft indica configurar auditoría para enviar alertas ante cambios en las propiedades o la membresía de Enterprise Admins y Domain Admins (ver 04.5).

7. Para no confundirse

  • Restricted Groups solo agrega miembros: no. Con Members, quita a todo el que no figure en la lista.
  • Restricted Groups sirve para controlar los grupos del domain: no. Microsoft no lo soporta para eso.
  • AppLocker es lo que Microsoft recomienda hoy para controlar aplicaciones: no. Recomienda App Control for Business; AppLocker solo recibe correcciones de seguridad.
