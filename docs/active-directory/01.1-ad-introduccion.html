Active Directory

Qué es y cómo funciona

Introducción

Qué es

Servicio de directorio de Microsoft, distribuido y jerárquico, que centraliza la administración de identidades y recursos de una organización: usuarios, grupos, equipos, impresoras, dispositivos de red, políticas y relaciones de confianza (trusts) entre dominios.

Toda esa información vive en una base de datos jerárquica (el directorio) que sirven los Domain Controllers.

Para qué sirve

  • Autenticación: verificar quién es cada usuario (un solo login válido en todo el dominio).
  • Autorización: decidir a qué puede acceder (grupos, permisos, ACLs).
  • Administración centralizada: políticas (GPO), altas y bajas de cuentas, delegación de tareas.

Cómo funciona

Domain Controller (DC)
Servidor que corre AD y guarda la base del directorio, el archivo NTDS.DIT (contiene usuarios, grupos y los hashes de las contraseñas de todo el dominio).
LDAP
Protocolo para consultar y modificar el directorio. Usa el puerto 389 (o el puerto 636 cuando es la versión cifrada con TLS, llamada LDAPS).
Kerberos
Protocolo de autenticación principal, basado en tickets. Usa el puerto 88.
NTLM
Protocolo de autenticación más viejo, tipo challenge-response (el server manda un desafío y el cliente prueba que conoce la password sin enviarla en texto plano). Se usa cuando Kerberos no se puede aplicar.
DNS
Protocolo que usan los clientes para encontrar a los DCs en la red (no para autenticar). Sin DNS funcionando, AD no funciona.

Estructura

Forest > Tree > Domain > OU (container) > objetos (leaf)

Ejemplo mental (TechCorp)

  • Forest: techcorp.local
    • Domain: techcorp.local
      • OU Finanzas — usuarios, equipos
      • OU Sistemas — usuarios, equipos
      • OU Domain Controllers — DC01, DC02

Cuando hay más de un domain o forest, se conectan entre sí mediante trusts (relaciones de confianza).

Idea clave: AD es la base de datos de identidades más los servicios de autenticación y autorización sobre ella. Todo lo demás (GPO, trusts, FSMO, ACLs) se apoya en eso.
