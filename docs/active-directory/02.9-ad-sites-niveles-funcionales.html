Active Directory

Sites y niveles funcionales

Fundamental

De qué trata

Dos configuraciones de AD que no agrupan objetos, como hacen las OUs o los grupos, y responden a preguntas distintas.

Sites

  • Topología física de la red
  • Qué subredes están bien conectadas
  • Cómo replican los DCs y a cuál se conecta cada cliente

Niveles funcionales

  • Un valor por domain y otro por forest
  • Qué funciones de AD están disponibles
  • Qué versiones de Windows Server pueden ser DC

Idea clave: Los sites organizan la red; los niveles funcionales deciden qué funciones y qué versiones de DC se permiten.

Sites

Un site es un conjunto de subredes IP bien conectadas entre sí, con enlaces rápidos. Sirve para dos cosas:

  • Ordenar la replicación entre DCs. Dentro de un site es rápida; entre sites es programada, para cuidar los enlaces lentos.
  • Que cada cliente use un DC cercano para autenticarse.
  • Relevante: si la subred de un cliente no está asociada a ningún site, puede terminar autenticándose contra un DC lejano. Es una causa típica de lentitud.
  • Un domain puede abarcar varios sites, y un site puede tener DCs de varios domains. No son lo mismo.
  • Una GPO puede linkearse a un site (ver 02.5).

Niveles funcionales

Un nivel funcional define qué funciones de AD están disponibles y qué versiones de Windows Server pueden ser DC.

Nivel del domain

  • Uno por cada domain
  • Habilita las funciones de ese domain

Nivel del forest

  • Uno por todo el forest
  • Habilita las funciones que abarcan todo el forest
  • Para subir el nivel del forest, todos sus DCs tienen que correr una versión de Windows Server compatible con ese nivel. El nivel de un domain nunca queda por debajo del del forest.
  • Subirlo es manual y conviene tratarlo como irreversible.
  • Riesgo: cualquier usuario del domain puede ver el nivel funcional. Un nivel bajo puede indicar DCs viejos y protecciones que faltan.

Funciones con valor de seguridad

2003
En el forest: forest trust y RODC. En el domain: selective authentication, lastLogonTimestamp y constrained delegation.
2008
AES para Kerberos, fine-grained password policies y SYSVOL con DFS-R.
2008 R2
Gestión automática de SPN para Managed Service Accounts. En el forest: la Recycle Bin (ver 02.6).
2012
Claims, compound authentication y Kerberos armoring.
2012 R2
Protected Users, authentication policies y silos.
2016
En el forest: Privileged Access Management (PAM). En el domain: nuevas protecciones de credenciales.

Es un resumen de lo que más pesa en seguridad, no una tabla completa. Windows Server 2019 y 2022 no agregaron un nivel nuevo, y Windows Server 2025 sí. Para el detalle actual, consultar la documentación de Microsoft.

Para no confundirse

  • Subir el nivel funcional actualiza los DCs: no. Solo habilita funciones; los DCs se actualizan aparte.
  • Un site es un domain: no. El site es topología física; el domain es un agrupamiento lógico.
  • Un site tampoco es una OU: el site es físico y la OU es lógica.
