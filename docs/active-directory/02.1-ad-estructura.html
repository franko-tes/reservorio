Active Directory

Estructura jerárquica

Fundamental

De qué trata este grupo

Todo lo que AD administra es un objeto, y los objetos no están sueltos: viven dentro de una jerarquía. Este grupo responde dos preguntas: qué puede existir (Object, Attributes, Schema) y dónde vive (Forest, Tree, Domain, Container, Leaf).

La jerarquía, de mayor a menor

  • Forest — el país: el contenedor más grande
    • Tree — domains que comparten namespace
      • Domain — la ciudad
        • Container (OU) — contiene otros objetos
          • Leaf — usuario, equipo… no contiene nada

Idea clave: El Schema atraviesa toda la jerarquía: define qué clases de objetos y qué atributos pueden existir en cualquier nivel.

Conceptos

1

Object

Cualquier recurso que existe en AD: usuarios, equipos, OUs, impresoras, Domain Controllers, GPOs. Es el término más amplio de todos.

2

Attributes

Características que definen a un objeto. Un equipo tiene, por ejemplo, hostname y DNS name; un usuario, nombre, apellido y mail.

Cada atributo tiene un nombre LDAP, y es ese el que se usa en las consultas, no el que se ve en la interfaz:

displayName
En la interfaz: Full Name.
givenName
En la interfaz: First Name.
3

Schema

El plano de todo el forest

Define qué tipos de objetos pueden existir y qué atributos tiene cada tipo (algunos obligatorios, otros opcionales). Los usuarios pertenecen a la clase user, los equipos a la clase computer, y así.

Crear un objeto a partir de una clase se llama instanciar, y el objeto resultante es una instancia de esa clase. Ejemplo: el equipo RDS01 es una instancia de la clase computer.

4

Domain

La ciudad

Agrupamiento lógico de objetos: usuarios, equipos, OUs, grupos. Puede operar de forma independiente o conectarse con otros domains mediante relaciones de confianza (trusts).

5

Forest

El país (o el estado)

Contenedor máximo. Tiene uno o varios domains y contiene todos los objetos: domains, usuarios, grupos, equipos y GPOs. Cada forest opera de forma independiente, aunque puede tener trusts con otros forests.

El forest es el límite de seguridad: es el perímetro dentro del cual todos los objetos están bajo un mismo control administrativo.

6

Tree

Conjunto de domains que arranca en un único domain raíz y comparten namespace. Un forest es una colección de trees. Al agregar un domain debajo de otro se forma una relación de confianza padre-hijo.

Dos trees del mismo forest no pueden compartir namespace. Ejemplo con dos trees:

  • Forest
    • Tree 1
      • techcorp.local — domain raíz
        • corp.techcorp.local — domain hijo
    • Tree 2
      • labcorp.local — domain raíz
        • corp.labcorp.local — domain hijo
7

Container

Objeto que puede contener otros objetos y tiene un lugar definido en la jerarquía del directorio. El ejemplo típico es una OU.

8

Leaf

Objeto que no contiene otros objetos: está al final de la jerarquía. Por ejemplo, un usuario o un equipo.

Para no confundirse

  • Un domain tiene un solo DC: no es así, un domain puede tener varios DCs. Cada DC guarda la copia completa de su propio domain y nada de los demás (salvo que sea Global Catalog, que guarda una copia parcial).
  • Las OUs cuelgan de un domain, nunca directamente del forest.
  • Un DC es un objeto más: vive en la OU Domain Controllers de su domain.
