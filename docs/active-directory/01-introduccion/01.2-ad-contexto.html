Active Directory

Por qué importa y contexto

Introducción

Por qué importa en seguridad

  • AD fue diseñado para ser retrocompatible con versiones viejas de Windows → muchas funciones no son seguras por default → es fácil de malconfigurar.
  • Es, en esencia, una base de datos de solo lectura accesible por cualquier usuario autenticado, sin importar su nivel de privilegio → una cuenta de dominio básica puede enumerar la mayoría de los objetos.
    • Equipos, usuarios y grupos del domain
    • OUs, GPOs y la Default Domain Policy
    • Password policy y niveles funcionales
    • Trusts y ACLs
  • Se estima que ~95% de las empresas Fortune 500 corren AD → es un objetivo de altísimo valor para atacantes.
  • Un DC comprometido o el NTDS.DIT (la base de AD) extraído significa todas las credenciales del dominio.

Anclaje histórico, en una línea: AD nace a partir de LDAP y del modelo de directorio X.500 (de los años 90), y llega a Windows recién con Server 2000.

AD on-premise vs Entra ID

AD (on-premise)

  • DCs propios
  • Kerberos, NTLM, LDAP
  • GPO y OUs clásicas

Entra ID (antes Azure AD)

  • Servicio de identidad en la nube
  • OAuth, OIDC, SAML
  • Sin GPO ni OUs clásicas

Entra ID no es "AD en la nube": es un servicio de identidad distinto, aunque cumple un rol equivalente.

Dos piezas que conectan ambos mundos

ADFS
Active Directory Federation Services: rol de Windows Server que permite SSO (inicio de sesión único) hacia aplicaciones fuera de la red local, usando tokens de seguridad. Es la base de SAML.
Azure AD Connect
La herramienta concreta que sincroniza un AD on-premise con Entra ID en el modelo híbrido.

Es común el modelo híbrido: AD on-premise sincronizado con Entra ID (vía Azure AD Connect).
