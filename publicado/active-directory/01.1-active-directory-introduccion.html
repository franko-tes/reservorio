Active Directory

Introducción
01.1 · Active Directory

Qué es

Servicio de directorio de Microsoft (incluido en Windows Server) que centraliza la administración de identidades y recursos de una organización: usuarios, grupos, equipos, impresoras, políticas.

Toda esa información vive en una base de datos jerárquica (el directorio) que sirven los Domain Controllers.

Para qué sirve

  • Autenticación: verificar quién es cada usuario (un solo login válido en todo el dominio)
  • Autorización: decidir a qué puede acceder (grupos, permisos, ACLs)
  • Administración centralizada: políticas (GPO), altas y bajas de cuentas, delegación de tareas

Cómo funciona

Domain Controller (DC)
Servidor que corre AD y guarda la base (NTDS.DIT)
LDAP
Protocolo para consultar y modificar el directorio (389 / 636 con TLS)
Kerberos
Autenticación principal, basada en tickets (88)
NTLM
Autenticación legacy por challenge-response, cuando Kerberos no es posible
DNS
Los clientes encuentran a los DCs por DNS. Sin DNS, AD no funciona

Estructura

Forest > Tree > Domain > OU (container) > objetos (leaf)

Ejemplo mental (TechCorp)
  • Forest: techcorp.local
    • Domain: techcorp.local
      • OU Financeusuarios, equipos
      • OU ITusuarios, equipos
      • OU Domain ControllersDC01, DC02

Por qué importa en seguridad

  • Quien controla AD controla la empresa: casi todo cuelga de ahí
  • Un DC comprometido o un NTDS.DIT extraído significa todas las credenciales del dominio
  • Por diseño, cualquier usuario autenticado puede leer gran parte del directorio, por eso la enumeración es una de las primeras cosas que hace un atacante

AD on-premise vs Entra ID

PRIMERA COLUMNA
  • AD (on-premise)
  • DCs propios
  • Kerberos, NTLM, LDAP
  • GPO y OUs clásicas
SEGUNDA COLUMNA
  • Entra ID (antes Azure AD)
  • Servicio de identidad en la nube
  • OAuth, OIDC, SAML
  • Sin GPO ni OUs clásicas

Entra ID no es "AD en la nube": es un servicio de identidad distinto, aunque cumple un rol equivalente.

Es común el modelo híbrido: AD on-premise sincronizado con Entra ID.

AD es la base de datos de identidades más los servicios de autenticación y autorización sobre ella. Todo lo demás (GPO, trusts, FSMO, ACLs) se apoya en eso.
